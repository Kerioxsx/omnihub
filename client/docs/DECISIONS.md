# Architecture decision log

## ADR-1 — Build with Gradle 8 + essential-loom instead of ForgeGradle 2.1 (2026-11-10)

**Context.** The official Forge 1.8.9 MDK (11.15.1.2318) uses ForgeGradle 2.1, which needs Gradle 2.7–2.14 and old Maven repositories; it does not run on modern JDKs and is fragile today.
**Decision.** Use `gg.essential.loom` 1.15.52 (Essential's maintained fork of architectury-loom with legacy Forge support) on Gradle 8.14. It consumes the **official** Forge `1.8.9-11.15.1.2318-1.8.9` artifacts and MCP `stable_22` mappings, compiles with a Java 8 toolchain and remaps to SRG names exactly like ForgeGradle's reobf.
**Verified.** `gradle build` produced a jar whose classes are Java 8 (major 52) with SRG member names (`func_…`/`field_…`); the same setup already ships OmniHub's kill-effects mod.
**Consequences.** Gradle runs on JDK 21; the JDK 8 toolchain is fetched by the foojay resolver. `gradle runClient` works for development (offline dev account).

## ADR-2 — Forge events and GuiScreen only; no ASM/Mixin (for now)

Everything so far is doable with Forge events (`GuiOpenEvent`, `RenderWorldLastEvent`, `RenderPlayerEvent`, `RenderGameOverlayEvent`, `ClientTickEvent`, `LivingDeathEvent` in singleplayer). No core mods or bytecode transforms, which keeps compatibility with OptiFine and other mods high. Revisit only with a demonstrated need.

## ADR-3 — Kill attribution tiers

`CONFIRMED` only from the integrated server in singleplayer/LAN (the server-side `LivingDeathEvent` with the local player as the damage source). `BEST_EFFORT` from an opt-in, per-server chat pattern (off by default, labelled). Nothing else counts as a kill: a target that disappears, teleports, unloads or disconnects never triggers a kill effect. Hit effects use the client's own attack (`AttackEntityEvent`), labelled `HIT_CONFIRMED` only in the sense "you swung at it", not that the server accepted the hit.

## ADR-4 — Original branding

Name **Vesper Client**; an original monoline sigil (no hexagram or other religious symbol, nothing from the reference client). Orbit tokens use original geometric glyphs, not cryptocurrency or other brand logos. No textures, models or audio are taken from the reference videos; all visuals are procedural (GL lines, quads, particles) or original files in `assets/vesper/`. Sounds use Minecraft's own sound events (nothing redistributed).

## ADR-5 — Where it lives and how it's installed

Source in the OmniHub repository (`client/`). Installation through OmniHub's existing 1.8.9 Forge profile setup (official launcher, Microsoft sign-in); the reference media stay out of the repository.

## ADR-6 — Agents and integration (2026-11-11)

Three specialist agents (vfx-engineer, cosmetics-animator, hud-pvp) ran in parallel git worktrees with strict package ownership. All three stopped partway when the account's usage limit was reached. Their unfinished files were merged by the lead and completed: the HUD elements and combat signals (hud-pvp), the particle system, effect framework, Astral Collapse and Violet Rift (vfx-engineer), and the palette/pose/batching helpers (cosmetics-animator). The lead wrote the remaining effects, skies, cosmetics, preview, showroom and HUD editor. The visual-director agent completed `VISUAL_SPEC.md`.

## ADR-7 — 3D models made in Blender from code

Wings, the thorn crown and the Skiff prop are generated by `models/vesper_models.py`, run in Blender 4.0 headless (`blender -b --python models/vesper_models.py -- <out> [renders]`), exported as OBJ and drawn by a small loader (`render/ObjModel`) with palette colours and baked shading. Keeping the models as code makes them reviewable, original and reproducible.

## ADR-8 — Sword animations without bytecode patching (2026-11-13)

Swing styles need control of the first-person item transforms, which Forge 1.8.9 has no event for. Instead of a core mod (ADR-2 still holds), Vesper puts a subclass of Minecraft's `ItemRenderer` in the two places that hold it (`Minecraft` and `EntityRenderer`), found by type through reflection. The subclass calls Minecraft's own code (`super`) whenever the module is off, for maps and for the empty hand, and otherwise reproduces the game's transforms before applying the chosen style. If the fields can't be found it logs once and leaves the game untouched. Swing speed changes only how the swing looks; the game's own attack timing is unchanged.

## ADR-9 — World lyrics come from OmniHub (2026-11-13)

Minecraft can't see what Windows is playing. OmniHub already has the song, its position and synced lyrics (Aurora), so it serves them read-only at `http://127.0.0.1:47830/vesper/lyrics` (this PC only; can be turned off in OmniHub). Vesper polls it twice a second on a background thread only while World lyrics is on and a world is open, and interpolates the position between answers.

## ADR-10 — Original effects only (2026-11-13)

The user pointed at another client for ideas (sky effects, funny kill animations, blur, FOV, hit animations, hit lines, world lyrics). Its files were not opened, run or copied, and its license forbids that. Everything in 0.2.0 was designed and written from the plain-language description: four new comic kill effects (Bonk!, Party Popper, Ghost Out, KA-POW!), three skies plus daylight/moon/Milky Way/shooting stars/motes, menu and motion blur, FOV and zoom, eight swing styles and four block-hit styles, hit lines and world lyrics.

## ADR-11 — Avatar model, original lookalikes, the six-point star (2026-11-13)

Emotes and the Wraith head need the player model's pose and head visibility, so `VesperPlayerModel` (a `ModelPlayer` subclass) replaces the model in each player renderer by reflection, applying changes only to your own player; everyone else is drawn by Minecraft's code. The user asked for a Roblox item's look (a headless head with horns) and emotes with real cars: Vesper ships an original take instead (a ghostly flame and Blender-made spiked horns, "Wraith head") and three unbranded cars made from code (`models/vesper_extras.py`), with no real car's name, shape or logo. ADR-4 kept religious symbols out of Vesper's branding; the six-point star is offered only as a jump-mark shape the user asked for, next to other shapes, and is not part of the brand. Hit sounds are synthesized from formulas (`sounds/make_hit_sounds.sh`), no samples.
